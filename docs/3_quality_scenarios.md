# 3. Сценарії якісних атрибутів (Quality Attribute Scenarios)

### Сценарій QAS-1: Performance Efficiency (Продуктивність під час пікового навантаження)
* **Source (Джерело):** Зареєстрований покупець.
* **Stimulus (Імпульс):** Надсилання HTTP POST запиту на створення замовлення під час масового розпродажу.
* **Environment (Середовище):** Пікове навантаження системи (Peak Load, 3 000 RPS).
* **Artifact (Артефакт):** API Gateway та Сервіс оформлення замовлень (Order Processing Module).
* **Response (Реакція):** Запит приймається в обробку, зберігається в асинхронній черзі подій (Message Broker), а користувач отримує відповідь `202 Accepted` з ID замовлення.
* **Response Measure (Міра реакції):** Час відповіді клієнту p99 < 200 ms, 0% втрачених замовлень (0% data loss), споживання пам'яті нодами < 85%.

---

### Сценарій QAS-2: Reliability (Відновлюваність при падінні бази даних)
* **Source (Джерело):** Апаратний збій основного вузла бази даних (Primary DB Node).
* **Stimulus (Імпульс):** Втрата зв'язку з основною СУБД під час виконання транзакцій.
* **Environment (Середовище):** Штатний режим роботи (Normal Operation).
* **Artifact (Артефакт):** Кластер баз даних (PostgreSQL Cluster / Patroni).
* **Response (Реакція):** Система відстеження стану (Health Check) виявляє відсутність відповіді, автоматично промоутить Standby-вузол до стану Primary та перенаправляє трафік.
* **Response Measure (Міра реакції):** Час автоматичного перемикання (Failover time) < 10 секунд, дані збережених транзакцій не втрачено (RPO = 0, RTO < 10s).

---

### Сценарій QAS-3: Security (Виявлення спроби несанкціонованого доступу)
* **Source (Джерело):** Зовнішній зловмисник (Атака типу Brute-force).
* **Stimulus (Імпульс):** Відправка 500 запитів автентифікації на хвилину з однієї IP-адреси з некоректними паролями.
* **Environment (Середовище):** Штатний режим роботи.
* **Artifact (Артефакт):** Сервіс автентифікації (Identity Provider / Keycloak) та API Gateway.
* **Response (Реакція):** Система фіксує перевищення ліміту запитів (Rate Limiting), тимчасово блокує IP-адресу на 15 хвилин та генерує сповіщення для Security Officer.
* **Response Measure (Міра реакції):** Блокування відбувається після 10-ї невдалої спроби, час реакції системи захисту < 1 секунди, подія зафіксована в Audit Log.

---

### Сценарій QAS-4: Maintainability (Внесення змін до доменної логіки)
* **Source (Джерело):** Розробник системи.
* **Stimulus (Імпульс):** Вимога додати новий спосіб розрахунку персональної знижки для VIP-клієнтів.
* **Environment (Середовище):** Етап розробки та CI/CD пайплайн.
* **Artifact (Артефакт):** Модуль розрахунку цін (Pricing Module).
* **Response (Реакція):** Розробник додає новий клас стратегії знижки без зміни існуючого коду інших модулів завдяки Clean Architecture.
* **Response Measure (Міра реакції):** Час на реалізацію та покриття тестами < 4 годин, 100% успішне проходження існуючих регресійних тестів.

---

### Сценарій QAS-5: Flexibility / Scalability (Автоматичне розширення ресурсів)
* **Source (Джерело):** Моніторингова система (Prometheus / Metrics Server).
* **Stimulus (Імпульс):** Зростання середнього навантаження на CPU сервісу каталогу понад 75% протягом 2 хвилин.
* **Environment (Середовище):** Режим підвищеного навантаження (High Load).
* **Artifact (Артефакт):** Інфраструктура Kubernetes (K8s / Horizontal Pod Autoscaler).
* **Response (Реакція):** HPA автоматично розгортає додаткові репліки (Pods) сервісу каталогу та балансує навантаження.
* **Response Measure (Міра реакції):** Додаткові репліки піднімаються та починають приймати трафік протягом < 60 секунд, середнє завантаження CPU знижується до < 50%.
