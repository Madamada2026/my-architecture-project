# ADR-0002. Вибір стратегії баз даних та збереження даних

## Статус
Accepted

## Контекст
Система E-Commerce має різнорідні типи даних: реляційні транзакційні дані (замовлення, платежі, користувачі), які вимагають суворої відповідності ACID, та каталоги товарів із гнучкою структурою атрибутів і високим навантаженням на читання.

## Рішення
Прийнято рішення використовувати підхід **Polyglot Persistence (Гібридне збереження даних)**:
1. **PostgreSQL** — як основна реляційна база даних для зберігання користувачів, замовлень, транзакцій та фінансових даних.
2. **Redis** — для кешування сесій, результатів популярних пошукових запитів та роботи з гарячими даними кошика.

## Розглянуті альтернативи
* **Використання виключно MongoDB (NoSQL):**
  * *Переваги:* Гнучкість схем.
  * *Мінуси/Чому відхилено:* Складність забезпечення суворих транзакцій ACID для фінансових операцій замовлень.
* **Використання виключно PostgreSQL без кешування:**
  * *Мінуси/Чому відхилено:* База даних стане «вузьким місцем» (bottleneck) при піковому навантаженні 3 000 RPS на каталог.

## Наслідки
* **Позитивні:**
  * Гарантія цілісності даних для платежів та замовлень (ACID).
  * Висока швидкість читання каталогу завдяки кешуванню у Redis (Latency < 20 ms).
* **Негативні / Компроміси (Trade-offs):**
  * Зростає складність інфраструктури (підтримка та моніторинг двох різних систем БД).
  * Необхідність вирішення проблеми інвалідації кешу в Redis.
