# ADR-0004. Вибір топології розгортання

## Статус
Accepted

## Контекст
Система E-Commerce Cloud Platform реалізована як Модульний моноліт (Clean Architecture) з використанням In-Memory шини подій. Нам потрібно визначити, як саме ця система буде розгортатися в середовищі розробки та на тестових серверах для демонстрації наскрізного сценарію.

## Рішення
Обрано топологію розгортання на базі **Docker (Single-Node)**. Оскільки на даному етапі використовується In-Memory шина, всі компоненти системи (WebAPI, фонові споживачі подій, бізнес-логіка) розгортаються в одному контейнері (або як один процес .NET). База даних (PostgreSQL) виноситься в окремий контейнер.

## Розглянуті альтернативи
* **Kubernetes (K8s):** Надмірно складно для поточного етапу. Потребує написання маніфестів та налаштування кластера, що не виправдано для модульного моноліту.
* **Розгортання на "голому" залізі (Bare Metal):** Проблеми з відтворюваністю середовища та складнощі з ізоляцією залежностей.

## Наслідки
* **Позитивні:**
  * Швидкий запуск однією командою `docker compose up`.
  * Ізоляція середовища.
  * Легкість демонстрації наскрізного сценарію.
* **Негативні / Компроміси (Trade-offs):**
  * Відсутність горизонтального автомасштабування на рівні окремих модулів.
  * При переході на реальний брокер (RabbitMQ/Kafka) доведеться виносити його в окремий контейнер.
